## 2. تفسير الجداول التي ليس لها سياسات RLS معلنة
- الجداول: `notifications`, `notification_deliveries`, `drive_seen_files`, `keepalive`.
- **التشخيص:** هذه الجداول مخصصة للمهام الخلفية (Background Workers / Cron / Edge Functions) مثل مزامنة Drive أو إرسال تنبيهات Telegram عبر البوت.
- **طريقة الوصول:** هذه المهام تستخدم مفتاح `service_role` من السيرفر الخلفي، وهو مفتاح يتجاوز RLS تلقائياً (Bypasses RLS). تفعيل RLS عليها بدون سياسات عامة هو سلوك صحيح أمنياً لعزلها ومنع أي متصفح خارجي أو مستخدم من العبث بها.

## 3. تدقيق نظام تسجيل الدخول الحالي (Telegram Login)
- **آلية العمل الحالية:**
  1. يسجل المستخدم دخوله عبر ويدجت تيليجرام (`MATHDEPARTMENT_BOT`).
  2. تُرسل بيانات التوقيع إلى الدالة السحابية `telegram-auth`.
  3. تقوم الدالة بالتحقق من صحة توقيع تيليجرام (HMAC-SHA256) وتنشئ رمز تحقق `token_hash`.
  4. يستدعي العميل `sb.auth.verifyOtp` ليحصل المستخدم على جلسة Supabase رسمية مشفرة بدور `authenticated`.
  5. يتم فحص جدول `profiles` للتأكد من حقل `approved`:
     - إذا كان `approved: false`: يتم إيقاف حسابه وعرض شاشة `SUSPENDED`.
     - إذا كان `approved: true`: يتم فحص الدور (`role`: `student`, `admin`, `full_admin`).

## 4. الرؤية الهندسية لتنفيذ الدخول المجهول (Anonymous Login) بأمان تام
عند الانتقال للمرحلة الثانية لتفعيل "الدخول المجهول للقراءة فقط":
- **الخيار الأول (الموصى به - Supabase Native Anonymous Auth):**
  - تفعيل خيار Anonymous Provider في Supabase Auth.
  - يستدعي المتصفح `sb.auth.signInAnonymously()`.
  - يحصل الزائر المجهول على توكن يحمل الخاصية: `(auth.jwt()->>'is_anonymous')::boolean = true`.
  - في سياسات RLS:
    - السماح للزائر المجهول بالقراءة فقط (`SELECT`) لجداول المحتوى العام (`courses`, `sections`, `items`, `posts`).
    - منع الزائر المجهول منعاً باتاً من التعديل أو الإضافة (`INSERT`, `UPDATE`, `DELETE`) أو الوصول لجداول `profiles`, `audit_log`, `progress`.
- **الخيار الثاني (Public Anon Grants):**
  - منح صلاحية `GRANT SELECT` لدور `anon` العام على جداول المحتوى الثابت والمفتوح فقط.
